# События Dr.Web ESS через SNMP traps

[English](README.md)

Пользовательский шаблон Zabbix для оповещений центрального сервера Dr.Web Enterprise Security Suite. Принимает SNMPv2c traps, декодирует UTF-8 Hex-STRING и создаёт проблемы с именем станции в названии события и теге `station`.

Названия элементов, триггеров и основные подписи расшифрованных событий — на русском языке.

## Какие проблемы создаются

| Событие | Важность |
| --- | --- |
| Обнаружена угроза | Высокая |
| Эпидемия | Чрезвычайная |
| Ошибка обновления станции | Предупреждение |
| Ошибка обновления репозитория | Средняя |
| Продукт заморожен из-за ошибки обновления | Средняя |
| Ошибка установки антивируса | Средняя |
| Истекает лицензионный ключ | Предупреждение |
| Лицензионный ключ истёк | Высокая |
| Лицензионный ключ заблокирован | Высокая |
| Ограничение числа станций или лицензии | Средняя |
| Число станций приближается к лимиту | Предупреждение |
| Ошибка соединения при продлении ключа | Предупреждение |
| Недостаточно места или inode на сервере ESS | Высокая |
| Станция давно не подключалась | Предупреждение |
| Давно нет связи с соседним сервером ESS | Средняя |
| Ошибка записи или ротации журнала сервера | Средняя |
| Ошибка авторизации станции | Предупреждение |
| Ошибка авторизации или неизвестный администратор | Предупреждение |
| Станции требуется перезагрузка | Информация |
| Массовые аварийные разрывы соединений | Предупреждение |

Общий префикс уведомлений — `1.3.6.1.4.1.29690.1.0`. Ошибки обработки файлов (`.16`, `.53`), HIPS, контроль приложений и остальные уведомления сохраняются в общей истории без отдельных триггеров. Тестовое сообщение `.35` записывается без создания проблемы.

## Настройка приёма traps

Если сервер Zabbix уже принимает traps, используйте действующую схему. Не заменяйте общие конфиги вслепую. Ниже приведён пример для Debian 13 с официальным Perl-приёмником Zabbix.

1. Установите пакеты:

   ```bash
   sudo apt install snmptrapd libsnmp-perl curl
   ```

2. Скачайте официальный приёмник из [репозитория Zabbix](https://github.com/zabbix/zabbix/blob/master/misc/snmptrap/zabbix_trap_receiver.pl). Он является внешней зависимостью и не включён в архив. Перед подключением ознакомьтесь с содержимым скрипта:

   ```bash
   sudo install -d -m 0755 /usr/local/lib/snmp
   sudo curl -fL https://raw.githubusercontent.com/zabbix/zabbix/master/misc/snmptrap/zabbix_trap_receiver.pl \
     -o /usr/local/lib/snmp/zabbix_trap_receiver.pl
   sudo chmod 0644 /usr/local/lib/snmp/zabbix_trap_receiver.pl
   ```

   В скрипте задайте путь:

   ```perl
   $SNMPTrapperFile = '/var/log/snmptrap/snmptrap.log';
   ```

3. Подготовьте каталог и файл. В Debian служба приёмника работает от `Debian-snmp`; процессу Zabbix нужен доступ на чтение. Числовой GID основной группы учётной записи службы помогает избежать конфликта одинаковых имён локальных и доменных групп:

   ```bash
   trap_reader_gid=$(id -g zabbix)
   sudo install -d -o Debian-snmp -g "$trap_reader_gid" -m 2750 /var/log/snmptrap
   sudo touch /var/log/snmptrap/snmptrap.log
   sudo chown "Debian-snmp:$trap_reader_gid" /var/log/snmptrap/snmptrap.log
   sudo chmod 0640 /var/log/snmptrap/snmptrap.log
   ```

   Если службы используют другие учётные записи, адаптируйте владельца и группу. Существующий журнал обнулять не нужно.

4. Добавьте в `/etc/snmp/snmptrapd.conf`, заменив оба параметра:

   ```conf
   authCommunity log,execute YOUR_COMMUNITY ESS_SOURCE_IP
   outputOption n
   perl do "/usr/local/lib/snmp/zabbix_trap_receiver.pl";
   ```

   `ESS_SOURCE_IP` — адрес отправителя, видимый приёмнику с учётом NAT. Макросы Zabbix здесь не раскрываются. Нужны числовые OID: обработчик шаблона ожидает формат `PDU INFO`/`VARBINDS` официального приёмника, а не произвольный вывод SNMPTT.

5. В конфигурации сервера Zabbix установите параметры без дублирования активных строк:

   ```ini
   StartSNMPTrapper=1
   SNMPTrapperFile=/var/log/snmptrap/snmptrap.log
   ```

   Примените настройки:

   ```bash
   sudo systemctl enable --now snmptrapd.socket
   sudo systemctl restart snmptrapd.service
   sudo systemctl restart zabbix-server.service
   ```

   При наличии фильтрации разрешите входящий UDP 162 от ESS. Если узел наблюдается через прокси, приём traps настраивается на этом прокси.

## Настройка ESS и импорт

1. В Центре управления ESS откройте **Администрирование → Конфигурация оповещений**. Добавьте или выберите способ отправки SNMP, укажите адрес приёмника Zabbix и ту же общность, что в `snmptrapd`. Сохраните настройки и включите отправку нужных типов оповещений. Расширение SNMP-агента для опроса включать ради отправки traps не требуется.
2. Импортируйте `templates/drweb_ess_snmp_zabbix.yaml` и привяжите **DrWeb ESS SNMP traps** к узлу центрального сервера ESS.
3. На узле задайте макрос `{$DRWEB.IP}` — адрес отправителя traps. По умолчанию в шаблоне он пустой.
4. В SNMP-интерфейсе узла укажите `{$DRWEB.IP}` в поле IP, выберите подключение **по IP**, порт оставьте `161`. Входящие traps принимает UDP 162; порт интерфейса не меняет порт приёмника.
5. Узел должен наблюдаться через сервер или прокси, принимающий traps. Сам шаблон не создаёт и не изменяет интерфейс узла.
6. Отправьте тестовое сообщение из ESS. После синхронизации конфигурации проверьте свежие значения в «Последних данных»: **Dr.Web: тестовое сообщение**, **Dr.Web: последнее событие, читаемый текст**, **Dr.Web: разобранное событие JSON**.

Существующий элемент `snmptrap.fallback` можно оставить. Сообщения, совпавшие с элементом шаблона, больше не попадают в fallback. Старые демонстрационные триггеры следует отключить, если они дублируют обработку.

## Проблемы, история и уведомления

- Каждое подходящее уведомление создаёт отдельную проблему, даже если проблема того же типа уже открыта. Закрытие — вручную после проверки; восстановления по таймеру нет.
- Узлом проблемы остаётся центральный сервер ESS, а затронутая станция берётся из уведомления. Для событий без станции используется подпись «Сервер Dr.Web».
- Имя события и теги фиксируются при его создании. Обновление шаблона не переименовывает старые проблемы.
- Исходные traps, JSON, читаемый текст и сообщения отдельных типов хранятся семь дней. В зависимости от события доступны имя/ID/адрес/группа станции, угроза, путь к объекту, действие, ошибка и данные лицензии.
- Для текста уведомлений в действиях Zabbix используйте `{ITEM.VALUE1}` — значение на момент события. В оперативных данных используется `{ITEM.LASTVALUE1}`: оно может показывать уже более позднее сообщение того же элемента.
- Действия, получателей и способы доставки уведомлений в Zabbix администратор настраивает отдельно.
