# PowerDNS dnsdist by HTTP

## Overview

This template monitors global [PowerDNS dnsdist](https://www.dnsdist.org/) metrics through the built-in HTTP API.

A single Zabbix HTTP agent master item retrieves the statistics in JSON format. All other metrics are collected as dependent items, which reduces the number of requests sent to dnsdist.

The template does not require Zabbix Agent or Zabbix Agent 2 on the dnsdist host.

Backend discovery and backend-specific metrics are intentionally excluded because backends can be monitored separately using their corresponding application templates.

### Monitored items

**Availability**

- dnsdist HTTP API availability
- dnsdist uptime
- Security status

**Query and response traffic**

- Received queries
- RD queries and empty queries
- Client and self-answered responses
- NOERROR, NXDOMAIN, and SERVFAIL responses
- Backend SERVFAIL responses

**Packet cache**

- Packet-cache hits and misses
- Five-minute packet-cache hit ratio

**Latency**

- UDP and TCP average latency
- UDP latency distribution
- Queries answered in more than one second

**Security and rules**

- ACL drops and dynamic blocks
- Non-compliant queries and responses
- Rule-generated drops and response codes
- Invalid Proxy Protocol events

**Performance and resources**

- CPU user and system time
- Resident memory usage
- Open file descriptors
- Downstream errors and timeouts
- UDP receive-buffer errors
- TCP listen overflows
- Query and response pipe-full events

### Triggers

| Trigger | Severity |
|---------|----------|
| dnsdist API statistics are unavailable | High |
| dnsdist security upgrade is recommended | Warning |
| dnsdist security upgrade is required | High |

### Graphs

The template includes graphs for:

- Query and response rates
- Response-code rates
- Packet-cache operation rates
- Packet-cache hit ratio
- UDP average latency
- Network error rates

## Requirements

- Zabbix Server or Proxy 7.4 or later
- PowerDNS dnsdist 2.x
- dnsdist built-in webserver and API enabled
- Network access from the Zabbix Server or Proxy to the dnsdist API port

No Zabbix agent is required on the dnsdist host.

## Setup

### 1. Enable the dnsdist webserver

Add a webserver configuration to `dnsdist.conf`. Replace the example addresses and API key with values appropriate for your environment:

```lua
webserver("192.0.2.20:8083")

setWebserverConfig({
  apiKey="HASHED-API-KEY",
  acl="192.0.2.10/32"
})
```

In this example:

- `192.0.2.20` is the dnsdist management address.
- `192.0.2.10` is the Zabbix Server or Proxy address.
- `HASHED-API-KEY` is the output generated by `hashPassword("YOUR-API-KEY")` in the dnsdist console.
- Zabbix and curl must still send the original `YOUR-API-KEY` value in the `X-API-Key` request header.

Store only the generated hash in `dnsdist.conf`; do not configure that hash as the Zabbix macro value. Restrict access using the dnsdist webserver ACL and a host or network firewall.

Restart or reload dnsdist after updating the configuration.

### 2. Verify API access

Run the following command from the Zabbix Server or Proxy that will monitor dnsdist:

```bash
curl --fail --silent --show-error \
  -H 'X-API-Key: YOUR-API-KEY' \
  http://192.0.2.20:8083/api/v1/servers/localhost/statistics
```

The endpoint should return dnsdist statistics in JSON format.

### 3. Import and assign the template

1. In Zabbix, go to **Data collection → Templates**.
2. Import `template_powerdns_dnsdist_by_http.yaml`.
3. Create or select the dnsdist host.
4. Configure the host's main interface with the dnsdist IP address or DNS name. The template uses `{HOST.CONN}` to build the API URL.
5. Link the **PowerDNS dnsdist by HTTP** template to the host.

### 4. Configure template macros

| Macro | Default | Description |
|-------|---------|-------------|
| `{$PDNS.DNSDIST.API.KEY}` | Empty | dnsdist API key sent in the `X-API-Key` header |
| `{$PDNS.DNSDIST.HTTP.TIMEOUT}` | `10s` | HTTP request timeout |
| `{$PDNS.DNSDIST.WEBSERVER.PORT}` | `8083` | dnsdist webserver port |
| `{$PDNS.DNSDIST.WEBSERVER.SCHEME}` | `http` | HTTP scheme, either `http` or `https` |

Set `{$PDNS.DNSDIST.API.KEY}` at the host level and store it as **Secret text**.

If a Zabbix Proxy monitors the host, the proxy must be able to connect directly to the dnsdist webserver.
